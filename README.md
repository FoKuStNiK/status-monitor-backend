# Status Monitor Backend — подробная инструкция для новичка

Это серверная часть проекта **«Мониторинг состояний»**. Она принимает сообщения от внешних программ, хранит состояния в SQLite и сообщает об изменениях открытым страницам сайта.

**Вы читаете README ветки `main`.** В ней frontend и backend запускаются отдельно через npm. Для Docker используется отдельная [ветка docker](https://github.com/FoKuStNiK/status-monitor-backend/tree/docker).

## 1. Из чего состоит сайт

Проект разделён на два репозитория:

| Часть | За что отвечает | Репозиторий |
| --- | --- | --- |
| Backend | HTTP API, приём Webhook, база данных, WebSocket | Этот репозиторий |
| Frontend | Таблица статусов, фильтры и интерфейс браузера | [status-monitor-frontend](https://github.com/FoKuStNiK/status-monitor-frontend) |

Схема работы:

```text
Внешняя программа
    |
    | POST /api/webhook (с токеном)
    v
Backend: Node.js / Express (порт 5000)
    |                   |
    v                   | WebSocket: новое состояние
SQLite                  v
                   Frontend: React (порт 3000)
                           |
                           v
                       Браузер
```

### Термины без сложных определений

- **Node.js** — программа, которая выполняет JavaScript на сервере.
- **Express** — библиотека для создания HTTP-сервера.
- **API** — адреса, по которым другие программы получают или отправляют данные.
- **Webhook** — сообщение, которое внешняя программа отправляет серверу через HTTP.
- **SQLite** — база данных в файле на диске.
- **WebSocket** — постоянное соединение с браузером, позволяющее отправлять обновления без перезагрузки страницы.
- **Git** — инструмент для скачивания кода и отслеживания его изменений.
- **npm** — инструмент для установки библиотек и запуска команд Node.js.

## 2. Что установить перед первым запуском

Установите [Git](https://git-scm.com/downloads) и [Node.js](https://nodejs.org/) версии **20 или новее**. Вместе с Node.js установится npm.

На Windows используйте Git Bash или PowerShell, на Linux/macOS — терминал.

Проверка установки:

```bash
git --version
node -v
npm -v
```

Если какую-то команду система не находит, установите соответствующую программу и **перезапустите терминал**.

## 3. Первый запуск: пошагово

### Шаг 1 — скачать оба репозитория

В выбранной вами папке выполните:

```bash
mkdir status-monitor
cd status-monitor
git clone https://github.com/FoKuStNiK/status-monitor-backend.git
git clone https://github.com/FoKuStNiK/status-monitor-frontend.git
```

Команда `git clone` скачивает проект с GitHub. Если вы уже скачали обе папки, повторять её не нужно.

Результат:

```text
status-monitor/
├── status-monitor-backend/
│   ├── package.json
│   ├── .env.example
│   ├── scripts/
│   └── server/
└── status-monitor-frontend/
    ├── package.json
    ├── public/
    └── src/
```

### Шаг 2 — перейти в backend

Из папки `status-monitor`:

```bash
cd status-monitor-backend
```

`cd` означает «перейти в каталог». Дальнейшие команды нужно выполнять **из папки backend**.

### Шаг 3 — установить библиотеки

```bash
npm install
```

npm читает `package.json` и устанавливает зависимости проекта в папку `node_modules`.

### Шаг 4 — создать свой файл настроек

В репозитории есть `.env.example` — образец. Создайте рядом файл `.env`.

Для **Git Bash / Linux / macOS**:

```bash
cp .env.example .env
```

Для **PowerShell**:

```powershell
Copy-Item .env.example .env
```

Это два **альтернативных** способа, а не две команды подряд.

Откройте созданный `.env`. Пример содержимого:

```dotenv
PORT=5000
DB_PATH=./server/data/statuses.db
FRONTEND_ORIGIN=http://localhost:3000
WEBHOOK_TOKEN=your-secret-token
```

**Обязательно замените `your-secret-token` на свой длинный случайный секретный токен.** Лучше создать уникальную строку с помощью менеджера паролей.

Что означают переменные:

| Переменная | Что настраивает |
| --- | --- |
| `PORT` | Порт, на котором запускается backend (по умолчанию 5000) |
| `DB_PATH` | Расположение файла с базой SQLite |
| `FRONTEND_ORIGIN` | Адрес frontend, которому разрешены запросы из браузера |
| `WEBHOOK_TOKEN` | Секрет для проверки отправителя Webhook |

Файл `.env` не должен попадать в GitHub: в нём могут быть секреты. Он исключён правилами `.gitignore`.

### Шаг 5 — запустить сервер

```bash
npm start
```

Команда запускает `node server/src/server.js`.

Откройте в браузере:
- [http://localhost:5000/api/health](http://localhost:5000/api/health) — ожидается `{"ok":true}`.
- [http://localhost:5000/api/statuses](http://localhost:5000/api/statuses) — список состояний в формате JSON. При первой установке это может быть `[]`.

**`localhost` — текущий компьютер**, на котором запущен backend, а не удалённый сайт.

**Не закрывайте терминал с сервером.** Пока он работает, перейдите к следующему шагу.

### Шаг 6 — запустить страницу сайта во втором терминале

Откройте **новое окно терминала**. Из папки backend выполните:

```bash
cd ../status-monitor-frontend
npm install
```

Создайте frontend-файл `.env` по [инструкции frontend](https://github.com/FoKuStNiK/status-monitor-frontend/blob/main/README.md). После этого:

```bash
npm start
```

Откройте [http://localhost:3000](http://localhost:3000) — это сам сайт.

Итак: **терминал № 1 — backend на 5000**, **терминал № 2 — frontend на 3000**.

### Шаг 7 — проверить на тестовых событиях

Поскольку база пока пустая, откройте **третий терминал** в каталоге `status-monitor-backend`:

```bash
npm run test:webhook
```

Скрипт отправит **50 тестовых Webhook-запросов** с ID от 1 до 10, случайными статусами и подробностями. Он использует токен из backend-файла `.env`.

Скрипт обращается строго к `http://localhost:5000/api/webhook`. Если сервер запущен на другом порту, URL в скрипте надо изменить.

В терминале ожидаются HTTP-ответы `200`. На странице должны появляться записи, меняющиеся без перезагрузки.

### Как остановить программы

В двух терминалах, где запущен `npm start`, нажмите **Ctrl + C**. Для повторного запуска обычно достаточно `npm start` в каждой папке — клонировать и устанавливать всё заново не надо.

## 4. Формат входящего сообщения Webhook

Внешняя программа должна отправить **POST** на:

```text
http://localhost:5000/api/webhook
```

С заголовками:

```text
Content-Type: application/json
Authorization: Bearer ВАШ_СЕКРЕТНЫЙ_ТОКЕН
```

Пример содержимого запроса (JSON):

```json
{
  "id": 15,
  "status": "worked",
  "timestamp": "2026-10-21T09:30:00.000Z",
  "details": "Тест: задача выполнена"
}
```

Поля:

| Поле | Значение |
| --- | --- |
| `id` | Положительное целое число (например, 15) |
| `status` | Один из шести разрешённых статусов |
| `timestamp` | Корректная строка даты; рекомендуется ISO 8601 с часовым поясом |
| `details` | Необязательная текстовая строка с подробностями |

Шесть разрешённых значений `status`:

```text
started
not connected
connected
worked
finished
error
```

Сервер хранит **только последнее состояние каждого ID**, а не историю всех сообщений. Событие со временем раньше сохранённого не перезапишет более новое. Пустое или отсутствующее `details` не стирает ранее записанные подробности.

## 5. Доступные адреса сервера

| Адрес | Назначение |
| --- | --- |
| `GET /api/health` | Проверить работу сервера |
| `GET /api/statuses` | Получить все состояния |
| `GET /api/statuses?id=15` | Получить состояние ID 15 |
| `GET /api/statuses?status=worked` | Выбрать записи по статусу |
| `GET /api/statuses?id=15&status=worked` | Применить оба фильтра |
| `POST /api/webhook` | Передать новое событие (нужен Bearer-токен) |
| `ws://localhost:5000/ws` | Получать новые состояния через WebSocket |

**GET** — запрос данных, **POST** — отправка данных, **JSON** — текстовый формат передачи информации.

## 6. Где хранится база

По умолчанию файл SQLite:

```text
status-monitor-backend/server/data/statuses.db
```

При первом запуске нужная папка и таблицы создаются автоматически, миграции выполняются из `server/src/migrations/`.

Во время работы SQLite может создавать дополнительные файлы с окончаниями `-wal` и `-shm`. **Не удаляйте их вручную при запущенном сервере.** Для надёжной эксплуатации делайте резервные копии базы.

## 7. За что отвечают файлы

| Файл или папка | Назначение |
| --- | --- |
| `package.json` | Библиотеки и npm-команды |
| `.env.example` | Образец настроек |
| `server/src/server.js` | Основной HTTP-сервер |
| `server/src/routes/` | Сопоставление адресов и обработчиков |
| `server/src/controllers/` | Проверка и обработка входящих запросов |
| `server/src/services/statusService.js` | Чтение и обновление состояний |
| `server/src/db.js` | SQLite и применение миграций |
| `server/src/sockets/statusSocket.js` | WebSocket и рассылка изменений |
| `scripts/sendTestWebhooks.js` | Тестовая отправка событий |

Для разработки есть `npm run dev`: эта команда запускает Node.js в режиме наблюдения за изменением файлов. Для обычного первого запуска используйте `npm start`.

## 8. Как обновить проект

В каталоге backend (предварительно остановив процесс):

```bash
git switch main
git pull origin main
npm install
npm start
```

`git switch main` выбирает основную ветку. `git pull` получает изменения с GitHub. Если на компьютере есть ваши собственные изменения, Git может не позволить обновление — сначала сохраните или разберите их.

Frontend обновляется **отдельно** в папке `status-monitor-frontend`.

## 9. Частые проблемы

| Симптом | Что проверить |
| --- | --- |
| `git`, `node` или `npm` не найден | Установлена ли программа? Перезапущен ли терминал? |
| `Cannot find module` | Выполнен ли `npm install` в нужной папке? |
| Порт 5000 уже занят | Не запущена ли ещё одна копия backend или другая программа? |
| `/api/health` не отвечает | Запущен ли backend, нет ли ошибок в его терминале? |
| Webhook возвращает `401` | Верен ли Bearer-токен? |
| Webhook возвращает `400` | Проверьте `id`, `status`, дату и тип `details` |
| Таблица пуста | Это нормально для новой базы; выполните тестовый скрипт |
| WebSocket не подключается | Работает ли backend и доступен ли порт 5000? |
| Ошибка CORS | Проверьте адрес frontend и `FRONTEND_ORIGIN`, затем перезапустите backend |

**Важно о публикации в интернете:** текущий `GET /api/statuses` не требует авторизации; Bearer-токен защищает только входящий Webhook. Для публичного сервера понадобятся HTTPS, настройка доступа и резервное копирование.

## 10. Где Docker

В ветке `main` работают два самостоятельных npm-процесса, без Docker. Если хотите контейнерный вариант, перейдите в [ветку docker](https://github.com/FoKuStNiK/status-monitor-backend/tree/docker) и используйте README из этой ветки. Там другая схема сборки и запуска.
